# candysign / xdp-mcp 客户端连接指南

> 这份文档解决一个问题：**当 `/mcp` 里什么都没有时，怎么从零把设备连上 Claude Code。**
>
> 平时你打开对话就能用，是因为 `.mcp.json` 和授权已经存在。换设备、换电脑、换项目目录、或别人第一次配，都要走下面的步骤。

---

## 0. 一句话原理

xdp-mcp 是一个部署在云上的 MCP 服务（程序名 `ionbridge-mcp`），地址 `https://mcp.thecandysign.com`。
它**没有登录页**，鉴权直接写在 URL 路径里：

```
https://mcp.thecandysign.com/<PSN>/<TOKEN>/sse
                              └─设备号─┘ └─口令─┘
```

- `PSN` = 设备序列号（每台机器不同）。
- `TOKEN` = 由 PSN 算出来的 8 位口令（每台机器固定，但不同 PSN 不一样）。
- 服务端拿 URL 里的 PSN/TOKEN 重新算一遍做常量时间比对，对得上才放行，并把这个 PSN 绑定到本次会话。

所以**“连一台新设备” = “换一个 PSN，重新算 TOKEN，重写 URL”**。其余都一样。

---

## 1. 前置条件

- 安装了 Claude Code。
- 知道目标设备的 **PSN**（序列号）。当前在用的：`1932000022957933`。
- 本机能访问 `mcp.thecandysign.com`（设备本身在线、能连 MQTT，工具才有数据返回；纯连接不依赖设备在线）。
- `python3`（用来算 token，系统自带即可）。

---

## 2. 步骤一：用 PSN 算出 TOKEN

算法：`sha256(PSN + "Ve0wNDVp")` 取十六进制摘要的第 `[28:36]` 位（8 个字符）。
盐 `Ve0wNDVp` 是固定的，和服务端 `auth.go` 里的 `DeriveToken` 完全一致。

```bash
python3 -c "import hashlib,sys; psn=sys.argv[1]; print(hashlib.sha256((psn+'Ve0wNDVp').encode()).hexdigest()[28:36])" 1932000022957933
```

输出：

```
33cb72c7
```

> 自检：`1091390003001045` 应得 `9eba6a5d`。对得上说明脚本没抄错。

把这一步存成一个小函数也行，换设备时直接传新 PSN 就出新 token。

---

## 3. 步骤二：在项目里写 `.mcp.json`

在**你要使用 MCP 的那个项目根目录**下（比如 `IonBridge/`）建/改 `.mcp.json`：

```json
{
  "mcpServers": {
    "candysign-1045": {
      "type": "sse",
      "url": "https://mcp.thecandysign.com/1932000022957933/33cb72c7/sse"
    }
  }
}
```

要点：

- `url` 把 **PSN 和上一步算出的 TOKEN** 拼进去，结尾是 `/sse`。
- `type` 用 `sse`。（服务端也支持 Streamable HTTP，路径换成 `/mcp`，`type` 用 `http`；SSE 这条已验证可用，优先用它。）
- 服务名 `candysign-1045` 只是一个本地标签，可以随便起。**沿用旧名字的好处**：如果以前授权过同名 server，Claude Code 不会再弹“是否信任”的框，省一步（见步骤三）。换了名字就要重新授权一次。

---

## 4. 步骤三：授权这个 server

Claude Code 默认不会自动信任项目里的 MCP server，需要授权一次：

- **方式 A（推荐，自动）**：写好 `.mcp.json` 后重开 Claude Code，会弹窗问是否信任 `candysign-1045`，选 **Yes**。它会把名字写进 `.claude/settings.local.json` 的 `enabledMcpjsonServers`。
- **方式 B（手动）**：直接编辑项目的 `.claude/settings.local.json`，确保有其一：

  ```json
  {
    "enabledMcpjsonServers": ["candysign-1045"]
  }
  ```

  或者一次性信任本项目所有 MCP：

  ```json
  {
    "enableAllProjectMcpServers": true
  }
  ```

> 沿用旧服务名时，如果 `enabledMcpjsonServers` 里已经有 `candysign-1045`，这一步直接跳过——这就是“以前不用每次配”的原因。

---

## 5. 步骤四：让工具注册（关键，最容易踩坑）

MCP 工具是在**对话开始时**加载进当前会话的。如果你在一个已经开着的对话里才刚写好 `.mcp.json`，**这个对话里是用不了工具的**，`/mcp` 也可能看不到。

做法：**新开一个对话**（或重启 Claude Code）。新对话启动时会去连 server、注册那 18 个工具。

---

## 6. 步骤五：用 `/mcp` 验证

新对话里输入 `/mcp`，应当看到：

- `candysign-1045` 状态 **connected / authenticated**
- 工具数 **18 个**（get_device_info、get_charging_status、turn_on_port…）

看到这些就成了。

---

## 7. 步骤六：怎么“对话式”使用

连上后**不用记工具名、不用每次报 PSN**——PSN 已经绑死在这个 server 上了，直接用自然语言说需求即可：

- “哪几个口在充电？输出功率多少？” → 走 `get_charging_status` / `get_port_details`
- “把待机动画换成时钟” → `set_idle_display`
- “关掉 C4 口” / “再打开 C4” → `turn_off_port` / `turn_on_port`
- “这台机器的硬件规格、支持哪些功能？” → `get_machine_facts` / `get_device_info`

只有当一个对话里**同时连了多台设备**（`.mcp.json` 配了多个 server）时，才需要点名“用 candysign-1045 那台”。

---

## 8. 换一台新设备怎么办

整个流程压缩成 4 步：

1. 拿到新 PSN。
2. `python3 ...` 算新 TOKEN（步骤二）。
3. 改 `.mcp.json` 里那条 `url` 的 PSN 和 TOKEN（服务名可不动，省授权）。
4. 新开对话 → `/mcp` 确认 18 个工具。

---

## 9. 排错

| 现象 | 排查 |
| --- | --- |
| `/mcp` 里没有 candysign | `.mcp.json` 没在当前项目根目录 / 没新开对话 / 没授权 |
| connected 但工具调用报鉴权失败 | TOKEN 和 PSN 不匹配，重算步骤二；确认 URL 没多/少字符 |
| 工具能调但返回超时/空 | 设备不在线或没连上 MQTT；服务连接本身是好的 |
| 弹窗反复问信任 | 服务名每次都换了；固定一个名字并写进 `enabledMcpjsonServers` |

两条命令行自检（你自己在终端跑，不依赖 Claude Code）：

```bash
# 1) 服务在不在（不验鉴权，返回 200 即服务存活）
curl -s -o /dev/null -w "%{http_code}\n" https://mcp.thecandysign.com/SKILL.md

# 2) 鉴权通不通（握手成功会回 event: endpoint 和一个 session id）
curl -N https://mcp.thecandysign.com/1932000022957933/33cb72c7/sse
```

---

## 10. 安全注意 ⚠️

- **URL 里带 TOKEN = 带口令**。`.mcp.json` 等于明文存了一把钥匙。
- **不要把 `.mcp.json` 提交进 git/hg**。在 IonBridge 里建议把它加进 `.gitignore`。
- 给别人看截图/录屏前，先把 URL 里的 PSN/TOKEN 打码。
- 换设备旧 TOKEN 不会失效（它只是 PSN 的哈希），所以泄露了就等于那台设备一直能被控，谨慎对待。

---

## 附：服务端关键事实（便于理解，不用动）

- 程序名 `ionbridge-mcp`，框架 `mark3labs/mcp-go`。
- 路径式多租户：`WithDynamicBasePath` + `WithSSEContextFunc` 把 `/<psn>/<token>/` 解析出来，注入本次会话的 PSN 上下文。
- 鉴权：`auth.go` 的 `DeriveToken`，盐 `Ve0wNDVp`，取摘要 `[28:36]`，常量时间比对，PSN 在 Postgres `device_information` 里要查得到。
- 设备通信：MQTT 请求/响应（`device/<psn>/enduser/request|response/<id>`），protobuf 负载，按 PSN 缓存最近一帧端口/设备遥测。
- `GET /SKILL.md`：无需鉴权的服务说明清单（适合做存活探测）。
